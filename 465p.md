# fiki-py checks an IP-literal's contents only when the authority comes from an absolute URL, never when it comes from the Host header. Measured 2026-10-09 against py/v0.8.0 (e3173da) from heti: refusals.json case ip-literal-that-is-not-an-address is refused (SignatureMismatch, 'cannot be read') with url='https://[not-an-ip]/things', but ACCEPTED when the same request is verified as url='/things' with Host: [not-an-ip], which is how every server-side caller verifies (heti's vanilla dialect does exactly that). text-after-an-ip-literal is still refused on the Host path, but only because its base differs, not because the authority was read and refused. The 0.8.0 ruling (@5zrf8gjk, hostile #1 on #14) says an IP-literal must hold an IPv6 address or IPvFuture; the Host path should apply the same check. Probably worth a vector variant that supplies the authority via Host with a relative URL, and checking the other five ports for the same gap. heti asserts the divergence in tests/ephemeral/test_fiki_vectors.py REFUSALS_HETI_ACCEPTS so the fix shows up there as a failure.
