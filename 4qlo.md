# Publish the five ports to their registries. Deferred deliberately, not forgotten. NAMES ARE ALL FREE as of 2026-09-04, checked directly: pypi.org/fiki, crates.io/fiki, npmjs @bakobo/fiki AND unscoped fiki all return 404. That is the one part of this with a clock on it — a name taken by someone else is not recoverable, and claiming a placeholder is cheap. THE FRICTION IS NOT UNIFORM. Go needs no registry at all: 'go get github.com/bakobo/fiki/go' already works from the repo, and publishing means only tagging 'go/v0.1.0' in the submodule form Go expects. PyPI, crates.io and npm are each an account plus a workflow; all three support OIDC trusted publishing from GitHub Actions, so none of them needs a long-lived token, which matters because a PAT is the thing Daniel does not keep. MAVEN CENTRAL IS THE OUTLIER by a wide margin: it needs a Sonatype account, a verified namespace (groupId com.bakobo means proving control of bakobo.com), GPG-signed artifacts with a published key, and javadoc plus sources jars. Budget that separately from the other four. THE REAL DESIGN QUESTION IS VERSIONING, and it should be settled before the first publish rather than after: five artifacts implement ONE wire format, and if they version independently then 'which versions interoperate' becomes a question nobody can answer from the version numbers. Options are a single lockstep version across all five (simple, forces empty releases when only one port changes) or independent versions plus a declared vectors-format version each artifact states it satisfies (honest, more moving parts). Everything is 0.0.0 today, so nothing is committed yet. Also decide the fiki/@bakobo scoping question for npm before claiming either
