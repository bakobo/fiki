# Bring the go port to parity with vectors/keri/, the KERI profile of RFC 9421's vector set (this.i @8vwrexxc, @7f28p7xk, @6g9zjsv9), which today only fiki-py generates and runs (py/tests/test_keri_vectors.py is the reference driver, vectors/keri/generate.py the reference semantics). What the port needs, all of which fiki-py gained in commit 38df6b1: (1) signResponse/verifyResponse covering @status and RFC 9421 section 2.4's req parameter, reading "@method";req, "@path";req, "@query";req and "content-digest";req from the paired request; any other component parameter, req in a request, @status in a request, or a request-derived component without req in a response refused as UnsupportedComponent, never dropped; (2) a caller-chosen keyid on sign and a caller-supplied resolver on verify (keyid -> 32 raw bytes or null), authoritative, never falling back to decoding the keyid, null meaning the new UnknownKey; (3) an optional minimum covered set on verify with the body rule (Content-Length>0, any Transfer-Encoding, or a non-empty body means a body, which needs a covered content-digest), refusing with the new InsufficientCoverage; (4) wire refusals: uppercase field names, unknown or wrongly typed signature parameters and non-inner-list members as MalformedSignatureInput, duplicates ignoring parameter order as the new DuplicateComponent, a non-64-byte signature as MalformedSignatureValue, either header with other than one label as MalformedSignatureLabel; (5) every recognized Content-Digest member must match; (6) verify raising in the profile's section 9 order (Signature before Signature-Input, covered list and coverage before the key, key before alg, stale before expired, malformed digest before mismatch); (7) a driver that maps the port's errors to the profile's kebab-case codes and asserts keri_vectors_format 1. The @method case fix is its own tick. None of this breaks the shared vectors.
