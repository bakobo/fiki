# vectors/keri/ has no case for two of the KERI profile's section 9 codes, because fiki cannot produce them: mode-mismatch (a legacy response to a canonical request; fiki has no legacy mode, @07wstqk7) and unsupported-signer (profile R4, a resolved key state with more than one signing key or a threshold other than one; fiki's resolver returns one key). Both are listed in refusals.json's codes array and exercised by no case. Options: have keripy's or signify-ts's own suite own those two cases, or extend the vector format with a key-state shape (signing keys plus threshold) and a legacy-response case that fiki would carry as static data it does not verify, as legacy.json already does. Also not covered for the same kind of reason: absent created (profile: REQUIRED, so malformed-signature-input; fiki accepts it when max_age is None) and the unsigned-401 exception of profile section 8.
